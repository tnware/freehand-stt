## Run a backend

Each provider page below is also listed under **Backend guides** in the docs
sidebar. The main site's **Backends** navigation opens the capability directory,
whose cards link to these same guides.

| Server | Launch instructions | Freehand operation |
| --- | --- | --- |
| whisper.cpp | [Native Windows](./whisper-cpp/#run-natively-on-windows) or [Docker](./whisper-cpp/#run-whispercpp-with-docker) | Transcription with a server-loaded model |
| vLLM | [Windows + Docker, NVIDIA GPU](./vllm/#run-vllm-with-docker) | Qwen3-ASR transcription or S1-mini cleanup |
| Speaches | [Docker GPU or CPU](./speaches/#run-speaches-with-docker) | Transcription; optional speech playback |
| llama.cpp | [Native Windows server](./llama-cpp/#run-llamacpp-on-windows) | S1-mini or compatible custom cleanup |
| Generic OpenAI-compatible | [Connect an existing endpoint](./generic/) | The operations implemented by your server |

These local examples use PowerShell and loopback ports. Docker recipes require
Docker Desktop with Linux containers; NVIDIA examples also require a working
WSL2 GPU setup. Follow [Docker's GPU setup](https://docs.docker.com/desktop/features/gpu/)
if `docker run --gpus ...` cannot access the card. First use downloads the image
and the selected model. Model weights stay in the recipe's folder or named
volume when a container stops.

Choose a model that fits the GPU memory available after other applications.
Smaller models can trade recognition quality for lower latency; being able to
list a model does not establish its quality. Stop an unused inference server
before starting another if both models do not fit. Each recipe includes its
own stop/restart commands; Freehand does not manage these processes.

For a remote or hosted server, use the same profile with the administrator's
HTTPS base URL, model ID, and authentication instead. Loopback-bound examples
are for a client on the same PC. See [connection topologies](../guides/connect-a-server/#choose-a-topology)
for separate STT, cleanup, and speech endpoints.

## What the labels mean

| Label | Evidence and limits |
| --- | --- |
| Available profile | Freehand implements a bounded contract and permits selection for the documented operations. |
| Automated contract fixtures | Local request/response fixtures cover the client behavior. They do not run a provider's models. |
| Reported working setup | A particular server/model combination has been used successfully. This is not a claim about every listed model or server release. |
| Planned profile | The dedicated option is disabled. A compatible server may already work through Generic. |

There is no certification or blanket approval of a provider. In particular,
**Test** reads health or model-list metadata only. It does not prove that a
model transcribes audio, accepts cleanup parameters, or returns playable speech.

## Choose profiles per operation

The microphone and stored-file workflows share the transcription connection.
Post-processing and speech playback each have their own connection and profile.
All three may use the same server or different servers. Endpoint, credentials,
model selection, and compatibility profile remain independent of the cleanup
prompt preset. Named saved connections are not implemented yet.

## Beyond the current contract

Optional transcription context and temperature are available through Generic
and the qualified Speaches, whisper.cpp, and vLLM transcription profiles, with hotwords through Speaches. Richer language shapes, timestamps, diarization, voice
instructions, reference-audio inputs, and progressive speech playback need
explicit client support and model qualifications. Selecting a provider profile
does not enable those features automatically.

Use the [protocol reference](../reference/protocol/) for exact request fields
and safety limits. Contributors should follow the
[catalog maintenance process](../development/backend-compatibility/) when adding
a profile, capability, or new validation evidence.
