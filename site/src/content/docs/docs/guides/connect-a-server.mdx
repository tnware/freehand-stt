---
title: Connect a speech server
description: Configure local, LAN, private remote, or hosted OpenAI-compatible speech services.
---

Connect Freehand to a speech service on your computer, another machine, or a
hosted provider. You need its base URL, model ID, and API key if it requires one.
This guide covers manually managed services. For installation inside Freehand,
use [Local runtimes](../local-runtime/) for supported recognition and cleanup
models on Windows and macOS. Text to speech still needs a manual connection.

Save a server once, then choose it for any task it supports. See
[Saved connections](../saved-connections/) to manage multiple servers.

## Start from your task

Choose **Voice**, **Audio file**, or **Text to speech**, then **Add connection…** in its connection
picker. Enter the server details and choose **Save and return**, then select a
model. Save your model settings to return to the task. You can also add a server
under **Settings → Connections**.

- **Voice dictation** is the default task. It needs STT and a microphone;
  complete its readiness screen before recording. A recording shortcut is optional.
  Use one to start with another application's text field focused, or use the
  on-screen controls and copy the result explicitly.
- **Audio file** has its own speech-to-text connection and model. It does not
  require a microphone or recording shortcut.
- **Text to speech** needs its own speech connection, model and voice ID, and
  **Enable text to speech** under **Settings → Text to speech**. It needs no STT
  connection and can be used before dictation setup.

Optional **Cleanup** sends the transcript to a chat model for editing. Leave it
off to use the speech model's original text. Configure cleanup separately from
transcription and text to speech.

## Decide where models run

A local GPU is optional. If your PC has limited memory, or you want its GPU
available for other work, use a speech service on another machine or a compatible
hosted provider. Network speed and the server affect response time.
Audio or text goes to the endpoint you choose, so its data handling policy also
applies.

Local inference is equally supported when you want to use this PC's resources.
Freehand is free forever; any chosen provider, server rental, or other hosting
costs are separate.

## Choose a topology

Tasks can share one gateway or use different servers. Each task keeps its own
model and options. Tasks using the same saved connection share its address and
authentication.

### One gateway

```text
Freehand
  ├─ STT ───────────────┐
  ├─ transcript cleanup ├─ https://speech.example.com/v1
  └─ TTS ───────────────┘
```

Use this when one compatible gateway exposes every route and model you need.
Save the gateway once in Connections and enable the uses it exposes. Each feature
selects it independently and keeps its own model/options. A metadata check does
not verify support for every enabled operation.

### Separate services

```text
Freehand
  ├─ STT ──────────────── Speaches or another compatible speech server
  ├─ transcript cleanup ─ llama.cpp or another compatible chat server
  └─ TTS ──────────────── Speaches or another compatible speech server
```

Use this when models live on different machines or runtimes. A cleanup outage
does not invalidate successful STT: Freehand preserves and delivers the raw
transcript.

Compare supported tasks in the [backend directory](../../../backends/),
or browse the [backend guides](../../backends/).

## Choose a language

Open **Settings → Voice transcription** or **Audio-file transcription** and
search the language picker by name or code. **Server default** uses your server's
language setting; **Automatic detection** asks it to identify the language.
Choose a language your model supports, or use **Custom server value** if your
server requires a value that is not listed.

See [language selection](../languages/) for provider mappings and S1-mini's
English-only cleanup behavior. Language selection does not request translation.

## Choose a compatibility profile

Choose the server software under **Backend** when adding or editing a connection:

| Connection                            | Available profiles                                     |
| ------------------------------------- | ------------------------------------------------------ |
| Speech to text (microphone and files) | Generic OpenAI-compatible, Speaches, whisper.cpp, vLLM, NeMo-Speech.cpp |
| Cleanup (optional stage after STT)    | Generic OpenAI-compatible, llama.cpp, vLLM             |
| Text to speech                        | Generic OpenAI-compatible, Speaches, Kokoro-FastAPI, vLLM-Omni |

Choose the profile matching your server. For another OpenAI-compatible service,
use **Generic OpenAI-compatible** and check its [requirements](../../backends/generic/).
Support depends on the server version and model; follow the relevant
[backend guide](../../backends/) before enabling additional tasks.

The **Model profile** is a separate choice in task settings. It adds controls
for a particular model, such as S1-mini cleanup or Nemotron live transcription.
See [Model profiles](../../models/).

Choose **Save connection** to store the profile and endpoint. Select that entry
on the relevant task page, then choose its model and save. Changing an existing
connection's URL or backend clears its model selections and remembered options;
choose the models again for the new server.

## Information Freehand needs

For speech to text, collect:

- the base URL including its API prefix, normally `/v1`;
- the exact transcription model ID expected by the server, except whisper.cpp
  which uses the server-loaded model;
- the authentication mode and API key, if required;
- any additional non-secret gateway headers required for transcription;
- whether the endpoint is intentionally using plaintext HTTP.

For example:

```text title="Example gateway settings"
Base URL: https://speech.example.com/v1
Model: speech/stt
Authentication: API key (only if required)
```

For Generic, Speaches, vLLM, and NeMo-Speech.cpp, Freehand appends `/audio/transcriptions`.
For whisper.cpp, enter the server root without `/v1`; Freehand appends
`/inference`. Do not enter the complete operation URL.

## Local and LAN servers

`http://127.0.0.1:8000/v1` and a private address such as
`http://192.168.1.50:8000/v1` are plaintext connections. Freehand rejects them
until **Allow HTTP for this connection** is enabled in that saved connection.

Only enable plaintext HTTP on a network you trust. Audio, transcript text, and
credentials sent over HTTP are not encrypted in transit. Prefer HTTPS for a
server reached across machines whenever practical.

## Test without invoking a model

Freehand checks a configured health path or `GET /v1/models`. It reports:

- whether the server was reachable;
- HTTP status and request latency;
- a stable failure category;
- discovered model IDs when the response has a compatible model-list shape;
- whether the currently configured model appears in that list.

The check never sends audio or a prompt. **Model list received** means the
server returned a valid model inventory; **Server reachable** means the
configured health endpoint responded successfully. An HTML gateway page or a
malformed model list is an **Invalid response**, even with HTTP status 200.
An empty valid model list is accepted, with the configured model **Not listed**.
Neither check verifies that a model can transcribe or synthesize audio, or that
an endpoint actually enforces the supplied credential.

The optional **Custom health path** is appended beneath the base URL path.
For example, `https://speech.example.com/v1` with `/health` checks
`https://speech.example.com/v1/health`, not the host-root `/health`.
Include the leading slash in the field. If that health check fails, Freehand
reports the failure without trying the model list instead.
Leave the custom path blank to use the backend's default check: `/health` for
whisper.cpp, or model-list metadata for other backends.

On the initial **Voice** setup screen, choose **Check connection** before
**Finish setup**. Freehand then checks that saved connection on launch and when
relevant connection settings change. If a check fails, correct the problem and
retry. These checks never run the listed models.

## Transcription controls

Choose options separately under **Settings → Voice transcription** and
**Audio-file transcription**. Voice shows context hints with its model options
and temperature under **Request settings**. Audio files group these under
**Transcription controls**. Only options supported by the selected backend and
model profile are available. Save before starting a new transcription.

| Setting               | Use                                                                                                                                | Availability                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Transcription context | Short subject matter or examples of expected wording. Leave blank if you do not need a hint. | Generic, Speaches, whisper.cpp, and vLLM; model and mode support varies. |
| Vocabulary | Names and phrases to favor during recognition. Edit the shared list under **Settings → Vocabulary** and enable it for each task. | See [Vocabulary](../vocabulary/) for supported combinations and limits. |
| Override temperature | Set a value from 0 to 1. Leave off to use the server default. Higher values can produce more variation. | Generic, Speaches, whisper.cpp, and vLLM; model and mode support varies. |

Context and vocabulary help recognition; they do not guarantee spelling or edit
words after transcription. Use [Cleanup](../post-processing/) for editing.
Keep context short: Freehand allows up to 8,192 UTF-8 bytes, including vocabulary
when it is sent as context, but your model may accept less.

These hints are saved in local settings and sent to your transcription server
when used. Do not put API keys or other secrets in them.

To compare an option, transcribe a short sample with your chosen model, change
one setting, and transcribe again. A connection check does not test whether the
model uses these hints. Freehand reports a rejected request without automatically
retrying it with different options.
