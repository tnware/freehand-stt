The app can optionally pass each successful raw speech-to-text result to a separate OpenAI-compatible `POST /chat/completions` endpoint before delivery. Speech recognition and cleanup have independent endpoints, models, and credentials. The raw transcript is retained first when history is enabled.

If post-processing fails, is unavailable, or returns empty text, the run falls
back to the raw transcript. Delivery still follows the normal destination
checks or explicit-copy setting; cancellation prevents automatic insertion.

## Choose a workflow

| Choice | Configuration |
| --- | --- |
| Leave transcription unchanged | Keep **Cleanup** off; no chat endpoint is needed. |
| Use your own cleanup model | Enable processing, select **Custom instruction**, and supply a compatible chat endpoint and model. |
| Use S1-mini by Superwhisper | Enable processing, select its dedicated profile, and connect a server hosting that English cleanup model. |

:::tip[Compare both versions]
Cleanup changes text and can make mistakes. Enable **History** before a run if
you want to compare or copy the raw and cleaned versions after successful
processing. History is off by default, limited to 20 entries and 2 MiB, and
cleared when Freehand exits. Raw fallback on cleanup failure does not require
history.
:::

## Custom-instruction processor

In **Settings → Post-processing**:

<Steps>

1. Enable transcript post-processing.
2. Enter the processor's OpenAI-compatible base URL, normally ending in `/v1`.
3. Enable **Allow insecure HTTP** only for a trusted local or LAN server using `http://`.
4. Add the processor's API key when that endpoint requires one.
5. Test the connection and select a discovered model, or enter the exact model ID supplied by your server. This check reads metadata; it does not test cleanup quality.
6. Choose **Custom instruction** and write the system instruction for the selected model. Freehand shows the UTF-8 storage limit, validates empty or oversized instructions, and can restore the recommended instruction.
7. Choose **Save changes**. Dictate a short example and review the result before using cleanup for longer text.

</Steps>

The system instruction is stored with the rest of the ordinary Freehand settings; the API key remains in Windows Credential Manager. The app sends a non-streaming chat completion with temperature `0`. The raw transcript is the separate user message, so the instruction does not need a transcript placeholder. Freehand does not send the speech-to-text credential to the processor.

Endpoint model IDs and request behavior are deliberately independent. A local or remote server may assign any model ID, so Freehand never guesses that a model needs the S1-mini contract from its name. Switching profiles preserves each profile's stored controls so switching back does not discard the custom instruction or S1-mini choices.

## S1-mini by Superwhisper with llama.cpp

[S1-mini by Superwhisper](https://huggingface.co/superwhisper/s1-mini) is an English transcript normalizer rather than a general chat model. Its prompt format and non-thinking template are exact requirements. A normal transcript repeatedly producing an empty response usually means the inference runtime did not disable Qwen thinking mode.

Install the current llama.cpp Windows package from PowerShell:

```powershell title="Install llama.cpp"
winget install --exact --id ggml.llamacpp
```

Open a new PowerShell window after installation, then start the server with reasoning disabled:

```powershell title="Start S1-mini with reasoning disabled" {4}
llama-server.exe `
  -hf superwhisper/s1-mini-GGUF:Q4_K_M `
  --jinja `
  --reasoning off `
  --temp 0 `
  -ngl 99 `
  --sleep-idle-seconds 60
```

This is a known-working Freehand setup. `-hf` downloads and caches the
Q4_K_M model from Hugging Face on first use. The command requests GPU offload;
use a host with available GPU capacity. For CPU-only inference, replace
`-ngl 99` with `-ngl 0 --device none`. See the upstream
[server options](https://github.com/ggml-org/llama.cpp/tree/master/tools/server#command-line-options).

<details>
<summary>Keep the model warm or release idle memory</summary>

[`--sleep-idle-seconds 60`](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#sleeping-on-idle)
unloads the model and its associated memory after one idle minute, then reloads
it for the next request. Omit this option when consistently warm response time
is more important than releasing idle resources.

</details>

The default OpenAI-compatible base URL is:

```text title="Cleanup endpoint base URL"
http://127.0.0.1:8080/v1
```

Configure **Settings → Post-processing** as follows:

```text title="Settings → Post-processing"
Enabled:             On
Endpoint:            http://127.0.0.1:8080/v1
Allow insecure HTTP: On
Model:               select the model returned by Test
Profile:             S1-mini
API key:             empty
```

Choose **Save changes** after configuring the profile. Try a short English dictation with history enabled so you can compare both versions.

The S1-mini profile sends the model's exact system prompt and control line and sets temperature `0`. Full Processing settings display the effective instruction and generated control line without allowing the fixed S1 contract to be edited. Reasoning is a backend concern rather than a portable OpenAI chat-completions field, so the runtime must disable it; current llama.cpp releases use `--reasoning off`.

### Input length and alpha limits

:::caution[Review long cleanup results]
The S1-mini v1 model card recommends inputs below roughly 1,000 tokens.
Freehand currently sends each cleanup input in one request; it does not split
long transcripts into sentence chunks or enforce an output length relative to
the input. A nonempty response can be accepted even if the server reports that
generation reached its length limit. Review cleaned output for omissions,
especially for long recordings and stored files, or leave cleanup off.
:::

The styling, structure, and context controls are limited to values on which S1-mini was trained. See [ADR 0001](../../decisions/0001-s1-mini-post-processing/) for the request contract and design constraints.
