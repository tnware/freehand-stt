Choose **Voice** to dictate into another application, **Audio file** to transcribe a recording, or optional **Text to speech** to listen to text. Voice and audio files use the same configured speech endpoint.

New installations use a capsule overlay with an envelope visualizer, minimal
surface, bottom-center position, 85% opacity, and 70% glow. Adjust these under
**Settings → Overlay**. The optional **Show Freehand** shortcut starts unassigned;
open the app from its tray icon or assign a shortcut in Settings.

## Voice dictation

Choose a recording style:

| | Toggle recording | Hold to talk |
| --- | --- | --- |
| Start | Press the shortcut once | Press and hold the shortcut |
| Stop | Press it again | Release it |
| Default shortcut | <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>Space</kbd> | Unassigned; configure under **Settings → Shortcuts** |
| Optional silence stop | Available when voice detection and automatic stop are enabled | Waits for shortcut release |

<Steps>

1. **Focus the text field** where the transcript should appear.
2. **Start recording** with your toggle or hold-to-talk shortcut. Wait for
   Freehand to show that recording has started, then speak.
3. **Stop recording** with the same shortcut or by releasing the held chord.
4. **Wait for transcription and any enabled cleanup.** Keep the original text
   field focused for direct insertion.

</Steps>

:::note[When to copy the result]
If the original application or focused control changes, Freehand leaves the
transcript available to copy. Manual-copy delivery also requires an explicit
copy action, even if the original field remains focused.
:::

### Toggle recording

Press the toggle shortcut once to begin and again to stop. When local voice detection and automatic stop are both enabled, a toggle recording can also finish after speech has been detected and the configured silence countdown expires.

The destination is captured when recording begins. If that destination is no
longer safe when transcription finishes, Freehand leaves the result available
to copy instead of inserting it elsewhere.

### Hold to talk

Press and hold the configured chord, speak, then release it to stop. Automatic
silence ending does not stop a hold-to-talk recording before you release the
shortcut.

A hold-to-talk chord may use the normal modifier-plus-key forms or a supported modifier-only combination. See [Shortcut policy](../../reference/shortcuts/) for the exact accepted key grammar and default bindings.

### Long dictation and VAD

Voice activity detection (VAD) identifies speech and silence locally using WebRTC. It is built in and enabled by default. Silence trimming, automatic stop, and checkpoints are separate options that start disabled. Together they can provide:

- stable live speech/silence feedback;
- leading and trailing silence trimming with retained context;
- speech-armed automatic stop for toggle recordings;
- pause-aware checkpoints for longer dictation.

Checkpoints prefer natural pauses but still enforce a hard segment limit; they do not guarantee a boundary only between thoughts. Checkpoint requests are sequential and assembled in order. Freehand still performs one final focus-safe insertion rather than pasting partial segments while you speak.

## Audio files

<Steps>

1. **Open Audio file** and choose **Choose audio** to select a recording.
2. **Choose the response mode.** Use completed output, or streaming when your
   server supports it.
3. **Select Transcribe** and wait for the result. Use **Cancel** to stop active work.
4. **Copy the completed transcript** explicitly into the application you want.

</Steps>

Selecting a file does not upload it until you start transcription. File
results never insert automatically because no destination was captured.

If streaming is rejected or its response is incompatible, the request stops.
Freehand remembers that streaming is unavailable for that endpoint and model;
choose **Retry** to submit a new request in completed mode. This may repeat
server work or incur another charge, so Freehand never resubmits automatically.
A completed JSON response returned to the original streaming request is used
immediately without another upload.

If a typed transcript stream ends before its final transcript arrives, the job
fails and any accepted partial text remains available to copy. Cleanup does not
run on a failed partial transcript. Older Speaches streams signal completion
by closing the response, so their completeness cannot be checked with a final
event.

- Supported formats: FLAC, MP3, MP4, MPEG, MPGA, M4A, OGG, WAV, and WebM.
- Jobs can be cancelled.
- File work and microphone capture are mutually exclusive.
- Completed JSON and compatible server-sent-event responses are supported.

The interface shows the file name, size, progress, status, and transcript. It
does not expose the full path to page content.

## Current result and task settings

Home centers on the selected task and its **Current result**. Dictation keeps the
latest delivered transcript here too; Copy and Clear work with history off. A new
recording replaces that result. File results stay available until cleared or
replaced. If insertion could not complete, the result explains that copying is
needed; enabling history is not required for recovery.

Expand **Dictation settings** or **Transcription settings** below the result for
frequent connection, model, and cleanup choices. These quick changes apply
immediately. Microphone and delivery controls appear only for dictation. Text to
speech shows its own connection and links to its model and voice settings.

Each task has its own requirements. Audio file transcription does not require a
microphone, recording shortcut, or completed dictation setup. Text to speech does
not require a transcription connection. Dictation remains the default task.

Endpoint and credential changes belong in **Settings → Connections**. Feature
pages choose an active connection and model. Settings-page edits use **Save feature
settings**; switching an active connection applies immediately. Running jobs keep
their captured settings and credentials.

## Transcript cleanup

Freehand can send the raw transcript to an independently configured OpenAI-compatible chat endpoint after speech recognition.

- **Raw mode** leaves transcription untouched.
- **Custom instructions** use a bounded user-authored system instruction.
- **S1-mini** uses the model's exact trained v1 prompt and control vocabulary.

Freehand delivers raw text when cleanup is disabled or falls back to it when cleanup fails, times out, or returns empty output. Retaining both versions after successful cleanup requires history to be enabled before the run and the text to fit its memory limits. Read [Transcript post-processing](../post-processing/) before configuring S1-mini or a local llama.cpp route.

## History

:::tip[Keep both transcript versions for this session]
Enable history before a run if you want to compare raw and cleaned text.
History is off by default, stays in memory, holds at most 20 entries and 2 MiB,
and is cleared when Freehand exits. Copy anything you want to keep before quitting.
:::

Retained entries contain transcript text and limited run details.

History never retains audio, credentials, full file paths, or destination
details. Each copy action is explicit.

## Text to speech

Optional speech playback uses its own endpoint, model, voice ID, credential, transport policy, and request budget.

<Steps>

1. **Create a speech connection** under **Settings → Connections** and save its
   endpoint and authentication. In **Settings → Text to speech**, select that
   connection, set the model and voice ID, enable playback, and save feature settings.
2. **Open Text to speech** and enter the text you want to hear. Your unsent text
   survives switching tasks or visiting Settings, and is cleared when the window
   reloads or Freehand exits.
3. **Choose Speak** to generate and play the audio.
4. **Use the playback controls** to pause, resume, replay, stop, or explicitly
   save the generated audio.

</Steps>

You can also listen to retained completed transcripts. Generated audio remains
in memory until you clear or replace it, start a recording, or exit Freehand.

Playback starts on demand. Freehand does not automatically read every transcript aloud or provide a voice conversation mode.

## Status overlay and tray

The native overlay is enabled by default and can be disabled under **Settings → Overlay**. It mirrors bounded operational state such as recording, speech/silence, checkpoints, processing, and copy-required outcomes. It never renders transcript text or changes focus.

The tray can show or hide Freehand, open Settings or About, cancel active work,
copy an available recovery transcript, and quit.

:::note[Quit from the tray]
Choose **Quit** from the tray menu to exit Freehand. Closing the main or
Settings window only hides it; Freehand continues running. Quit cancels active
transcription and speech work. If you are saving generated audio, let the save
finish before quitting; an interrupted export can leave a partial WAV file.
:::

## Appearance

Under **Settings → General**, choose System, Light, or Dark. Dark uses Freehand’s
navy backgrounds and cobalt accents, matching the website across the main window,
Settings, and About. The recording overlay uses the same navy and cobalt palette;
red, green, and amber still identify recording and status.

Windows Mica is optional. It follows Windows appearance and uses a translucent
navy tint in dark mode, so the underlying system material can still affect the
result. Appearance changes that affect native windows apply after quitting from
the tray and reopening Freehand.
