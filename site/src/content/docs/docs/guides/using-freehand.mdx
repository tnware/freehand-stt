Freehand is a lightweight Windows client for speech-to-text and text-to-speech
services you choose. Choose **Voice** (the default) to dictate into another
application, **Audio file** to transcribe a recording, or optional **Text to
speech** to generate audio from your own text or listen to retained transcripts.
Each task can be used independently; the tabs remain available before dictation
setup is complete. Voice and audio files have independent transcription connections and models.
TTS has its own settings.

New installations use a capsule overlay with an envelope visualizer, minimal
surface, bottom-center position, 85% opacity, and 70% glow. Adjust these under
**Settings → Overlay**. The optional **Show Freehand** shortcut starts unassigned;
open the app from its tray icon or assign a shortcut in Settings.

## Check the active connection

Select the connection status at the bottom of the window to see the active
connection and model for the current task. **Check connection** or **Check again**
reads server metadata using your applied settings. It does not record, upload
audio, or run a model. The panel explains failed checks; **Technical details**
expands the individual checks and HTTP status.

**Edit connection** opens that saved connection in the connection manager. If
none is selected, **Choose connection** opens the manager for the current task.
Voice, Audio file, and Text to speech show their own connections and check
results. A check of unsaved Settings edits is not presented as a check of the
active connection. When text to speech is off, the panel links to **Speech
settings** instead of offering a check.

Escape closes the panel and returns keyboard focus to the footer status.

## Voice dictation

You need a usable microphone, a recording shortcut, and a configured STT service.
Complete the **Voice** readiness screen before your first recording; see
[Run your first dictation](../../getting-started/#run-your-first-dictation).

Choose a recording style:

|                       | Toggle recording                                              | Hold to talk                                         |
| --------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| Start                 | Press the shortcut once                                       | Press and hold the shortcut                          |
| Stop                  | Press it again                                                | Release it                                           |
| Default shortcut      | <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>Space</kbd>         | Unassigned; configure under **Settings → Shortcuts** |
| Optional silence stop | Available when voice detection and automatic stop are enabled | Waits for shortcut release                           |

<Steps>

1. **Focus the text field** where the transcript should appear.
2. **Start recording** with your toggle or hold-to-talk shortcut. Wait for
   Freehand to show that recording has started, then speak.
3. **Stop recording** with the same shortcut or by releasing the held chord.
4. **Wait for transcription and any enabled cleanup.** Keep the original text
   field focused for direct insertion.

</Steps>

:::note[When to copy the result]
If the original application or focused control changes, Freehand leaves the
transcript available to copy. Manual-copy delivery also requires an explicit
copy action, even if the original field remains focused.
:::

### Toggle recording

Press the toggle shortcut once to begin and again to stop. When local voice detection and automatic stop are both enabled, a toggle recording can also finish after speech has been detected and the configured silence countdown expires.

The destination is captured when recording begins. If that destination is no
longer safe when transcription finishes, Freehand leaves the result available
to copy instead of inserting it elsewhere.

### Hold to talk

Press and hold the configured chord, speak, then release it to stop. Automatic
silence ending does not stop a hold-to-talk recording before you release the
shortcut.

A hold-to-talk chord may use the normal modifier-plus-key forms or a supported modifier-only combination. See [Shortcut policy](../../reference/shortcuts/) for the exact accepted key grammar and default bindings.

### Long dictation and VAD

Voice activity detection (VAD) identifies speech and silence locally using WebRTC. It is built in and enabled by default. Silence trimming, automatic stop, and checkpoints are separate options that start disabled. Together they can provide:

- stable live speech/silence feedback;
- leading and trailing silence trimming with retained context;
- speech-armed automatic stop for toggle recordings;
- pause-aware checkpoints for longer dictation.

Checkpoints prefer natural pauses but still enforce a hard segment limit; they do not guarantee a boundary only between thoughts. Checkpoint requests are sequential and assembled in order. Freehand still performs one final focus-safe insertion rather than pasting partial segments while you speak.

## Audio files

Configure the audio-file transcription connection and model, independently of Voice. You do not need a
microphone, recording shortcut, or completed dictation setup.

<Steps>

1. **Open Audio file** and choose **Choose** to select a recording.
2. **Choose the response mode.** Enable **Show text as it arrives** for streaming when supported, or disable
   it for completed output. The control remains in place while a file is processed.
3. **Select Transcribe** and wait for the result. Use **Cancel** to stop active work.
4. **Copy the completed transcript** explicitly into the application you want.
   Use **Change** to select another file, or **Again** to transcribe the current file again.

</Steps>

If transcription fails, choose **Details** beside the error to read the full
explanation. Escape closes the popover and returns focus to Details; **Retry**
starts another attempt with the selected file.


Selecting a file does not upload it until you start transcription. File
results never insert automatically because no destination was captured.

If streaming is rejected or its response is incompatible, the request stops.
Freehand remembers that streaming is unavailable for that endpoint and model;
choose **Retry** to submit a new request in completed mode. This may repeat
server work or incur another charge, so Freehand never resubmits automatically.
A completed JSON response returned to the original streaming request is used
immediately without another upload.

If a typed transcript stream ends before its final transcript arrives, the job
fails and any accepted partial text remains available to copy. Cleanup does not
run on a failed partial transcript. Older Speaches streams signal completion
by closing the response, so their completeness cannot be checked with a final
event.

- Supported formats: FLAC, MP3, MP4, MPEG, MPGA, M4A, OGG, WAV, and WebM.
- Jobs can be cancelled.
- File work and microphone capture are mutually exclusive.
- Completed JSON and compatible server-sent-event responses are supported.

The interface shows the file name, size, progress, status, and transcript. It
does not expose the full path to page content.

## Current result and task settings

Home centers on the selected task and its **Current result**. Dictation keeps the
latest delivered transcript here too; Copy, Clear, and Listen work with history off.
Listen appears when text to speech is enabled. A new
recording replaces that result. File results stay available until cleared or
replaced. If insertion could not complete, the result explains that copying is
needed; enabling history is not required for recovery.

The toolbar at the top of **Current result** keeps quick settings close at hand.
The microphone icon opens audio controls; the **Transcription** and **Cleanup**
provider buttons open connection, model, and processing options. In Voice, the delivery
icon opens direct-input and history controls. Audio file shows only its transcription
and cleanup controls. These changes apply immediately.
Copy briefly confirms success, then returns to its normal label. Hover over or
focus the history and playback action icons to see what they do.

Each popover links to its full Settings page. Press Escape to close it and return
to its toolbar button. Text to speech uses the same compact header: its **Speech** provider button opens
connection, model, voice, and supported speaking-speed controls. These changes apply
immediately to the next generation; **All speech settings** opens the full page.

With history enabled, wider windows show result and history side by side. Drag
the divider to change their widths, or focus it with Tab and use the arrow keys.
Freehand remembers the split. Each pane scrolls independently; opening quick
settings does not move the transcript. Long transcripts use a comfortable reading width.
Live text follows new words until you scroll back to read earlier text. Choose
**Jump to latest**, or scroll to the bottom, to resume following; finalization preserves
your position when you are reading back. Narrow windows use **Result** and
**History** view buttons to give each view the full width.

Endpoint and credential changes belong in **Settings → Connections**. Feature
pages choose an active connection and model. Settings-page edits use **Save
settings**; switching an active connection applies immediately. Running jobs keep
their captured settings and credentials.

## Transcript cleanup

For either dictation or audio files, optional **Settings → Cleanup** can send the
raw transcript to an independently configured OpenAI-compatible chat endpoint
after speech recognition. This is an optional STT stage, not a separate task or
a prerequisite for TTS.

- **Raw mode** leaves transcription untouched.
- **Custom instructions** use a bounded user-authored system instruction.
- **S1-mini** uses the model's exact trained v1 prompt and control vocabulary.

Freehand delivers raw text when cleanup is disabled or falls back to it when cleanup fails, times out, or returns empty output. Retaining both versions after successful cleanup requires history to be enabled before the run and the text to fit its memory limits. Read [Transcript post-processing](../post-processing/) before configuring S1-mini or a local llama.cpp route.

## History

:::tip[Keep both transcript versions for this session]
Enable history before a run if you want to compare raw and cleaned text.
History is off by default, stays in memory, holds at most 20 entries and 2 MiB,
and is cleared when Freehand exits. Copy anything you want to keep before quitting.
:::

Retained entries keep **Listen** and **Copy** directly available. Open the
ellipsis **Transcript actions** menu for **Transcription details** or **Remove
from history**. **Compare** opens raw and cleaned text together, with separate
copy controls. If cleanup fails, its explanation appears below the raw transcript.

History never retains audio, credentials, full file paths, or destination
details. Each copy action is explicit.

## Finding and adjusting settings

In a full-width Settings window, **Find settings** filters the sidebar by page
name or terms such as “padding,” “glow,” and “hotkey.” Enter opens the first match;
Escape clears the filter. Searching and changing pages keep your unsaved edits.

**Audio** keeps microphone selection, the recording limit, and the main silence
switches together. Open **Speech detection tuning** for sensitivity, padding,
minimum speech, and segment timing. Enabled automatic stop keeps its pause
control beside the switch.

**Overlay** keeps preview, layout, position, and size up front. Open **Appearance
and behavior** for surface, visualizer, visible phases, motion, spacing, opacity,
and glow. Minimal surfaces disable glow adjustment while keeping its saved value.
Preview uses your unsaved choices; **Save settings** applies them.

Model and model-profile fields have help buttons for their detailed explanations.
Profile menus show each profile's description before you select it. Voice uses
the same profile and language pickers in quick settings and the full Settings page.
Language pickers search by name or code; unrestricted lists keep **Custom server
value** available even when your search has no match. Restricted profiles offer
only their supported languages. Required restrictions and unavailable options
remain explained beside the affected controls.

The four workflow pages keep model selection and everyday options up front.
Open **Request settings** for timeouts and connection diagnostics; connection
warnings remain visible in its summary. **Transcription controls** groups context
and temperature for audio files, and **Generation controls** groups cleanup's
output and reasoning options. Voice transcription keeps context hints visible
and places its completed-recording timeout and temperature in **Request settings**.
Text to speech keeps **Preview** beside the voice selector, using your current
edits without saving them.

You can click a switch’s label to change it. Collapsing a tuning section keeps
its values, and a rejected save opens the section containing the affected field.

## Text to speech

In **Settings → Text to speech**, **Preview** beside the voice selector uses your current model,
model profile, voice, speed, and timeout edits before you click **Save settings**.
Turn on the draft **Enable text to speech** switch to preview even when the saved
feature is disabled. Preview generates only the fixed sample phrase; it does not
save your edits or enable playback elsewhere. Each preview keeps the options it
started with. Stop it and preview again to hear further changes.

Optional text to speech uses its own endpoint, model, voice ID, credential,
transport policy, and request budget. It is off by default and does not require
a microphone, recording shortcut, STT connection, or completed dictation setup.

<Steps>

1. **Open Text to speech**, then open **Speech** in the composer header to select
   a saved connection or **Add connection…**, then choose the model and voice directly.
   **Refresh models** and supported **Refresh voices** read metadata without generating
   audio; manual IDs work too. For initial setup, open **All speech settings**, choose
   the model profile, turn on **Enable text to speech**, and choose **Save settings**.
2. **Return to Text to speech** and enter the text you want to hear. Your unsent text
   survives switching tasks or visiting Settings, and is cleared when the window
   reloads or Freehand exits.
3. **Choose Speak** to generate and play the audio. Playback and save controls
   occupy a permanent area below the editor, so the editor stays the same size
   as generation and playback progress.
4. **Use the playback controls** to pause, resume, restart, stop, or explicitly
   **Save generated speech** to a file.

</Steps>

Text to speech accepts up to 4,096 Unicode characters. Longer drafts remain
editable; shorten the text to enable Speak.

You can also choose **Listen** on a completed Voice or Audio-file result, even
with history off, or on a retained history entry. Generated audio remains in memory until you clear or replace it, start a
recording, or exit Freehand.

Playback starts on demand. Freehand does not automatically read every transcript aloud or provide a voice conversation mode.

## Action feedback

Speech failures appear beside the playback controls. Open **Details** for the
full explanation and a shortcut to **Speech settings**. In the speech composer,
**Try again** generates speech from the text currently in the editor; a failed
request does not erase your draft. File and dictation errors also provide
**Details** with a shortcut to their transcription settings. A discarded
microphone recording cannot be retried; **Record again** starts a new recording
after you correct the problem.

Shared errors and confirmations appear above the footer without moving the
workspace. Speech-composer notices span the panel above its action and playback controls.
Long errors have expandable details. Confirmations disappear automatically;
errors can be dismissed. Copy confirmation stays on the copy control, and
clearing generated audio simply returns the player to its empty state.

## Status overlay and tray

The native overlay is enabled by default and can be disabled under **Settings → Overlay**. It mirrors bounded operational state such as recording, speech/silence, checkpoints, processing, and copy-required outcomes. With qualified realtime transcription, optional live captions show one row of provisional text. The overlay never changes focus.

The tray can show or hide Freehand, open Settings or About, cancel active work,
copy an available recovery transcript, and quit.

:::note[Quit from the tray]
Choose **Quit** from the tray menu to exit Freehand. Closing the main or
Settings window only hides it; Freehand continues running. Quit cancels active
transcription and speech work. If you are saving generated audio, let the save
finish before quitting; an interrupted export can leave a partial WAV file.
:::

## Appearance

Under **Settings → General**, choose System, Light, or Dark. Dark uses Freehand’s
navy backgrounds and cobalt accents, matching the website across the main window,
Settings, and About. The recording overlay uses the same navy and cobalt palette;
red, green, and amber still identify recording and status.

Windows Mica is optional. It follows Windows appearance and uses a translucent
navy tint in dark mode, so the underlying system material can still affect the
result. Appearance changes that affect native windows apply after quitting from
the tray and reopening Freehand.
